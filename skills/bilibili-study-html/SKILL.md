# B 站课程学习页

仅在用户显式调用 `$bilibili-study-html` 或点选本技能时使用。`agents/openai.yaml` 的 `policy.allow_implicit_invocation` 必须保持 `false`，不能仅因出现 B 站链接而自动运行。

## 输入与交付

接收教程链接和保存位置。用户给出本地文件名时按原路径保存；给出目录时可使用 `<BV号>-学习进度.html`。若尚未指定位置，可以先解析课程、准备临时文件，再询问交付位置，不自行建立线上仓库。

本地交付默认在 Windows 用户的实际桌面创建快捷方式，指向最终保存的 HTML，并使用与网页一致的课程 Logo；无需用户每次单独提出。用户明确不要快捷方式时遵从其要求。图标保存在 HTML 同目录的同名 `.ico` 文件中，移动 HTML 后需重新生成快捷方式。

用户选择线上发布时，先读 [references/online.md](references/online.md)，遵从其指定的托管平台、账户、仓库和可见性。已经明确授权的发布流程不必重复确认。

模板源：[Alexx-Powered/cpp-study-progress](https://github.com/Alexx-Powered/cpp-study-progress)，其中 `templates/学习进度模板.html` 是带源码注释的可复用版本。优先取 GitHub 最新模板；网络不可用时使用 `assets/template.html` 的快照，并在交付中说明回退。

保留模板现有的预览/手动每日统计、实际分钟进度、跨天复习红色叠加柱、空白日期过滤、深浅主题、固定顶部、跳转最新进度和图表动画。课程标题、分 P 数据、课程链接、存储命名空间都要更新，不能只换页面标题。预览选择 Pn 时只勾选 P1～Pn，不影响手动统计。

保留 `~` 跳过功能：`~11-15, 1-10` 表示跳过 11～15 集、学习前 10 集（也支持 `11~15`）。保存后和载入编辑时，跳过标记排在前面，已学分集放在末尾，便于继续更新。跳过分集按原始时长计入去重完成进度，但不计已学分钟、每日学习时间或柱状图；后续首次补学仍计为首次学习。每日记录分别保存 `episodes` 和 `skipped`，JSON v2 备份保留两者，并兼容 v1 旧记录与备份；原课程存储键保持稳定。

## 解析与生成

生成时根据课程主题设置浏览器标签页图标。模板的 `applyCourseIcon` 已按课程标题自动匹配 C++（含全角 C＋＋）和 Python（不区分大小写），使用内嵌 SVG，离线也能显示。其他课程若有明确的语言、软件或学科主题，在生成文件的图标字典和匹配规则中补充对应标识；标题不明确时结合分 P 标题判断，仍无法确定则使用书本图标。图标与识别规则都应嵌入 HTML，不依赖远程图片；同时更新 `<link id="courseIcon">` 的初始图标，避免加载时短暂显示其他课程的标识。不要沿用原 C++ 图标。

使用 Node.js 18+，无需第三方依赖。以下 `<skilldir>` 指本技能目录：

```text
node "<skilldir>/scripts/bilibili_study.cjs" create --url "<B站链接>" --output "<目标.html>" --metadata-output "<课程.json>"
```

也可分两步执行，方便检查课程数据或采用浏览器解析结果：

```text
node "<skilldir>/scripts/bilibili_study.cjs" fetch --url "<B站链接>" --output "<课程.json>"
node "<skilldir>/scripts/bilibili_study.cjs" build --metadata "<课程.json>" --output "<目标.html>"
```

`create` / `build` 默认自动渲染最终 HTML 中的内嵌 Logo，生成 `.ico` 并创建桌面快捷方式；使用已安装的 Edge/Chrome，独立临时浏览器配置，不读取用户浏览器资料。桌面位置由 Windows 的已知文件夹接口解析，支持重定向到 OneDrive 等位置。同名快捷方式指向其他文件时自动另取名称，不覆盖其他课程。

临时验证、尚未确定最终路径或仅供线上发布的构建使用 `--no-shortcut`。完成课程图标调整、移动至最终目录或发布后，再按交付目标执行：

```text
node "<skilldir>/scripts/bilibili_study.cjs" desktop --html "<最终保存的课程.html>"
```

快捷方式图标必须来自最终课程 Logo；若在首次生成后补充了主题图标，再运行 `desktop` 同步更新。若系统未安装可用的 Edge/Chrome，使用可用的隔离浏览器把同一内嵌 Logo 渲染成 16～256 像素的正方形 PNG，再加 `--icon-png "<Logo.png>"`。脚本失败时保留 HTML，并修复或说明未完成的快捷方式步骤，不能仅根据 HTML 生成成功就报告全部完成。

脚本优先使用 B 站公开接口 `/x/web-interface/view` 的 `data.pages`，以逐 P 的真实秒数生成时间。不能用总时长平均分配。链接中的 `p=N` 不限制解析范围；默认解析该视频全部分 P。`ugc_season` 是另一个合集维度，不能混入同一 BV 的分 P；若用户要整个合集，应说明范围并另行遍历各视频。

若接口被拒绝或结果不完整，使用可用的浏览器工具检查视频目录、页面已加载的结构化数据和实际分集时长。先读取该浏览器工具的操作说明；遇到登录或验证码交给用户处理，不绕过访问控制。浏览器得到的数据可以保存为以下规范 JSON，再运行 `build`：

```json
{
  "bvid": "BVxxxxxxxxxx",
  "title": "课程标题",
  "pages": [
    {"page": 1, "title": "分集标题", "durationSeconds": 891}
  ]
}
```

数据必须来自实际观察，P 编号从 1 连续到 N，不可补造缺失项。每项可附 `cid`、`stage`；明确的 `stage` 优先保留。缺省或为“课程分集”时，脚本与模板按原标题的章节标记、重复主题前缀自动生成阶段，忽略分集序号；同一主题即使出现在不同位置也归入同一阶段。无法识别的标题仍用“课程分集”，不继承上一集的阶段，不擅自改写原标题。脚本会校验编号和秒数，并把远程标题安全编码后嵌入 HTML。

默认存储前缀是 `bilibili-<小写BV号>`，避免与原 C++ 页面串数据；需要同课程的独立副本时使用 `--storage-prefix "<独立前缀>"`。指定另一个兼容模板可用 `--template "<模板.html>"`。

输出存在时默认拒绝覆盖。仅在覆盖属于用户请求时加 `--overwrite`，脚本会先留下同目录备份。本地与线上页面的浏览器存储互不自动迁移；不要把用户学习记录、登录状态或浏览器资料夹打包上传。

## 核验与回报

确认阶段名称和筛选后的分集与原标题对应；保留人工阶段，不把每一集的完整标题都当作一个阶段。

确认标签页图标对应课程主题，内嵌图标能被浏览器加载，首次加载和脚本初始化后的图标一致。

本地交付时读取生成的 `.lnk`，核对目标为最终 HTML、IconLocation 为对应 `.ico`，并确认图标文件存在。测试使用 `--shortcut-dir "<临时目录>"`，不要在真实桌面留下测试快捷方式。报告成品位置与桌面快捷方式名称。

检查实际分 P 数、首尾标题、编号连续性和时长总和；页面总分钟、每集链接应与课程元数据一致。用隔离浏览器上下文打开新文件，验证预览不会改写每日统计、两天重复学习可显示红色复习柱，且主题、过滤和动画仍有效。不要向用户原页面注入测试记录。

报告生成文件或已核验的在线地址、分 P 数和总分钟；注明实际使用的模板来源，以及任何未完成的解析/发布步骤。除非用户要求，不把调试数据作为页面内容。

示例：

```text
使用 $bilibili-study-html，把 https://www.bilibili.com/video/BV1sHU9BmEne/ 做成学习进度页面，保存到 D:\Learning\PythonAI。
使用 $bilibili-study-html，解析这个 B 站教程，并在我的 GitHub 新建公开仓库，用 GitHub Pages 发布。
```
