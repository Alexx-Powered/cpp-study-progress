# 线上交付

先在本地生成并验证 HTML，再发布。遵从用户选择的平台；用户只说“线上”时，可建议 GitHub Pages 或询问目标，不擅自选用付费服务。

## GitHub Pages

- 查看已登录的 GitHub 账户，确认用户指定的仓库。新仓库先检查名称是否可用；已有仓库先读目录和部署配置，保留无关文件。
- 只发布生成的 HTML、必要入口和简短使用说明，不上传工作区、临时测试记录或浏览器数据。新仓库可以用 `index.html` 和 `.nojekyll`；已有仓库按其结构放置，避免覆盖其他课程。
- 创建仓库、设为公开、推送代码、启用 Pages 均应在用户请求的范围内。“新建公开仓库并发布”已涵盖这些正常步骤，不重复要求授权。仅“保存本地”不涵盖任何线上写入。
- 对普通静态 HTML，新仓库可用主分支根目录部署。GitHub REST 的 Pages 创建参数示例：`{"source":{"branch":"main","path":"/"},"build_type":"legacy"}`。已有仓库应保留其部署方式。遇到接口变化时查阅[官方 Pages API 文档](https://docs.github.com/en/rest/pages/pages#create-a-github-pages-site)。
- 等待构建结果，匿名请求实际 Pages 地址，再用浏览器检查页面初始化。仓库公开不等于网站已部署；不要把推测的 URL 当作已上线结果。

其他托管平台按当前工具、平台文档和用户指定目标操作，不把 GitHub 流程硬套过去。

发布失败时保留本地成品并说明缺少的权限、账户或构建条件。若需要改变仓库、域名、付费方案或可见性才能继续，先请求用户方向；不要扩大已授权范围。

页面使用当前浏览器的 localStorage 保存学习记录。线上访问不会自动带入本地文件页面的进度；如需迁移，另行协助导出/导入，不把个人进度默认写进公开源码。
